# Mollika Inn — Rails 8+ Application Architecture Design

**Prepared for:** Mollika Inn Hotel Owner  
**Current site:** https://www.mollikainn.com/ (WordPress/Elementor static site)  
**Target stack:** Ruby on Rails 8+ with Hotwire, PostgreSQL, Active Storage, Solid Queue

---

## 1. Executive Summary

The current Mollika Inn website is a static WordPress/Elementor site with four pages (Home, Accommodation, Gallery, Facilities, Contact Us) and zero dynamic capability. Guests cannot book online, the owner cannot manage content without a developer, and there is no operational system behind the site.

This document defines the full structure, architecture, and feature set to rebuild Mollika Inn as a modern Rails 8 application — giving guests a seamless booking experience and giving the hotel owner complete control via a built-in admin panel.

## 3. Rails 8+ Technology Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | **Rails 8.x** | Full-stack, batteries-included, rapid iteration |
| Frontend | **Hotwire (Turbo + Stimulus)** | SPA-like experience without heavy JavaScript build pipeline |
| Real-time | **Action Cable + Turbo Streams** | Live availability updates, instant booking confirmation |
| Background jobs | **Solid Queue** (Rails 8 default) | Email notifications, booking reminders, report generation |
| Caching | **Solid Cache** (Rails 8 default) | Fragment caching for room listings, gallery, availability |
| WebSockets | **Solid Cable** (Rails 8 default) | Backed by the database, no Redis dependency |
| File storage | **Active Storage** | Room photos, gallery images, stored to cloud (S3/Cloudflare R2) |
| Authentication | **Rails 8 built-in auth generator** | `rails generate authentication` — sessions, passwords, password reset |
| Database | **PostgreSQL** | Robust, handles concurrent bookings safely |
| Email | **Action Mailer + Postmark/SendGrid** | Booking confirmations, reminders, admin alerts |
| Payments | **Stripe** (or bKash/Nagad for Bangladesh) | Secure online payment with webhook reconciliation |
| Deployment | **Kamal 2** (Rails 8 default) | Docker-based zero-downtime deploys via SSH |
| CSS | **Tailwind CSS + DaisyUI or custom theme** | Utility-first, warm boutique hotel aesthetic |

## 5. Database Schema

### `room_types`
```
id, name, slug, description, max_occupancy,
bed_type, size_sqm, base_price_per_night,
amenities (jsonb), created_at, updated_at
```
Seed data: Single Room, Double Room, Deluxe Room, Family Room

### `rooms`
```
id, room_type_id, room_number, floor, status (available/maintenance/occupied),
notes, created_at, updated_at
```

### `rates`  _(seasonal / weekend pricing)_
```
id, room_type_id, name, price_per_night,
start_date, end_date, day_of_week (nullable), priority, created_at
```

### `guests`
```
id, first_name, last_name, email, phone,
nid_or_passport, address, nationality,
password_digest (optional — for guest portal), created_at
```

### `bookings`
```
id, guest_id, check_in_date, check_out_date,
num_adults, num_children, status (pending/confirmed/checked_in/checked_out/cancelled),
total_amount, paid_amount, payment_status (unpaid/partial/paid),
payment_method, stripe_payment_intent_id,
special_requests, cancellation_reason,
confirmed_at, cancelled_at, created_at, updated_at
```

### `booking_rooms`  _(one booking → one or more rooms)_
```
id, booking_id, room_id, room_type_id,
rate_per_night, total_amount
```

### `availabilities`  _(manually blocked dates — maintenance, owner hold, etc.)_
```
id, room_id, blocked_date, reason, created_at
```

### `gallery_albums`
```
id, name, description, position, visible, created_at
```

### `gallery_images`
```
id, gallery_album_id, caption, position, created_at
# + Active Storage attachment: image
```

### `facilities`
```
id, name, description, icon_name, category, position, visible, created_at
```

### `reviews`
```
id, booking_id, guest_id, rating (1-5), title, body,
cleanliness_rating, service_rating, value_rating,
approved, created_at
```

### `contact_inquiries`
```
id, name, email, phone, subject, message,
status (new/read/replied), replied_at, created_at
```

### `settings`  _(key-value store for hotel configuration)_
```
id, key (unique), value, description
```
Keys: `hotel_name`, `hotel_phone`, `hotel_email`, `hotel_address`, `check_in_time`, `check_out_time`, `cancellation_policy`, `booking_advance_days`

## 6. Routes

```ruby
Rails.application.routes.draw do

  # --- Public Guest-Facing ---
  root "home#index"

  resources :rooms, only: [:index, :show]

  resources :bookings, only: [:new, :create, :show] do
    collection do
      get  :check_availability   # AJAX: returns available rooms for date range
      post :hold                 # Turbo: hold a room for 15 min while guest fills form
    end
  end

  get  "/gallery",    to: "gallery#index"
  get  "/facilities", to: "facilities#index"
  get  "/contact",    to: "contacts#new"
  post "/contact",    to: "contacts#create"
  get  "/about",      to: "home#about"

  resources :reviews, only: [:new, :create]

  # --- Guest Portal (optional Phase 2) ---
  namespace :guests do
    resource :session, only: [:new, :create, :destroy]
    resource :profile, only: [:show, :edit, :update]
    resources :bookings, only: [:index, :show] do
      member { patch :cancel }
    end
  end

  # --- Admin Panel ---
  namespace :admin do
    root "dashboard#index"

    resources :rooms do
      resources :availabilities, only: [:index, :create, :destroy]
    end
    resources :room_types do
      resources :rates
    end
    resources :bookings do
      member do
        patch :confirm
        patch :check_in
        patch :check_out
        patch :cancel
      end
    end
    resources :guests
    resources :gallery_albums do
      resources :gallery_images, only: [:create, :destroy, :update]
    end
    resources :facilities
    resources :reviews do
      member { patch :approve }
    end
    resources :contact_inquiries, only: [:index, :show, :update, :destroy]
    resource  :settings, only: [:show, :update]
    resources :reports, only: [:index] do
      collection do
        get :occupancy
        get :revenue
        get :bookings_export  # CSV download
      end
    end
  end

  # --- Auth (Rails 8 built-in) ---
  resource  :session,  only: [:new, :create, :destroy]
  resources :passwords, param: :token

  # --- Stripe Webhooks ---
  post "/webhooks/stripe", to: "webhooks/stripe#receive"

end
```

## 7. Key Feature Modules

### 7.1 Availability & Booking Engine

**How it works:**

1. Guest picks check-in / check-out on the home page date picker (Stimulus controller).
2. A Turbo Frame request fires `GET /bookings/check_availability?check_in=…&check_out=…`.
3. Rails queries `booking_rooms` + `availabilities` to compute available room types and count.
4. Turbo replaces the room listing frame with live availability badges and prices (with seasonal rate applied).
5. Guest clicks "Book Now" on a room → goes to `/bookings/new?room_type_id=…&check_in=…&check_out=…`.
6. Booking form collects guest details; on submit, creates `Booking` (status: `pending`) + `BookingRoom` record.
7. Stripe payment link is generated; guest pays → Stripe webhook fires → booking status → `confirmed`.
8. `BookingConfirmationJob` sends email to guest and hotel admin.

**Overbooking prevention:** A DB-level unique partial index + pessimistic locking during `booking_rooms` insert prevents race conditions.

### 7.2 Admin Dashboard

Accessible at `/admin` (protected by `AdminAuthentication` concern — Rails 8 auth).

**Dashboard widgets (Turbo Frames, auto-refresh every 60s):**
- Today's arrivals / departures
- Current occupancy % by room type
- Revenue this week vs last week
- New bookings pending confirmation
- Unread contact inquiries
- Low-rated reviews awaiting moderation

### 7.3 Dynamic Room Management

Admin can:
- Add / edit / archive room types with rich description and amenity checklist
- Upload multiple photos per room type (Active Storage, drag-to-reorder)
- Set base price and seasonal rates (date ranges)
- Block specific dates per room (maintenance, owner hold)
- Toggle room status: Available / Under Maintenance

### 7.4 Gallery Management

Admin can:
- Create albums (e.g., "Rooms", "Common Areas", "Surroundings")
- Upload images in bulk (Active Storage, direct upload to S3/R2)
- Drag-to-reorder images within albums (Stimulus + Sortable.js)
- Toggle album visibility

### 7.5 Booking Lifecycle & Notifications

```
pending → confirmed → checked_in → checked_out
              ↓              ↓
          cancelled      cancelled
```

| Event | Guest Email | Admin Email | SMS (optional) |
|---|---|---|---|
| Booking created (pending) | Pending confirmation notice | New booking alert | - |
| Booking confirmed | Confirmation + details | - | Confirmation |
| Check-in reminder | 24h before check-in | Day's arrival list | Reminder |
| Check-out reminder | Morning of check-out | - | - |
| Booking cancelled | Cancellation + refund info | Cancellation alert | - |

All emails sent via **Solid Queue** background jobs — no blocking the request cycle.

### 7.6 Reviews System

- Only guests with a completed (`checked_out`) booking can submit a review
- Review form sent via booking confirmation email (unique token URL)
- Admin moderates before public display
- Aggregate ratings shown on room detail pages and homepage

### 7.7 Contact & Inquiry Management

- Public contact form → creates `ContactInquiry` record
- Admin notified by email (Solid Queue job)
- Admin marks as read / replied from the dashboard
- Reply button opens pre-filled email compose (mailto or embedded email form)

## 10. Hotwire Pattern Examples

### Live Availability Search (Turbo Frames)
```erb
<%# app/views/home/index.html.erb %>
<%= turbo_frame_tag "availability_results", src: check_availability_bookings_path do %>
  <p>Enter your dates above to see available rooms.</p>
<% end %>
```
The date picker Stimulus controller updates the frame `src` on change → instant results, no page reload.

### Real-time Booking Counter (Turbo Streams via Action Cable)
```ruby
# When a booking is confirmed, broadcast to admin dashboard
Turbo::StreamsChannel.broadcast_prepend_to(
  "admin_bookings",
  target: "bookings_list",
  partial: "admin/bookings/booking_row",
  locals: { booking: @booking }
)
```

### Inline Room Status Toggle (Hotwire)
```erb
<%# Admin room list — toggle maintenance status without page reload %>
<%= button_to toggle_status_admin_room_path(room),
      method: :patch,
      data: { turbo_stream: true } do %>
  <%= room.status %>
<% end %>
```

## 11. Security Considerations

| Concern | Mitigation |
|---|---|
| Admin access | Rails 8 built-in `Authentication` — bcrypt passwords, secure session tokens, rate-limited login |
| Payment data | Never store card data — Stripe handles tokenisation; only store `payment_intent_id` |
| SQL injection | ActiveRecord parameterised queries — no raw SQL |
| Mass assignment | Strong parameters in every controller |
| CSRF | Rails default `protect_from_forgery` on all non-webhook routes |
| Stripe webhooks | Verify `Stripe-Signature` header before processing |
| Guest PII | Encrypted `email`, `phone`, `nid_or_passport` fields using `attr_encrypted` gem |
| File uploads | Active Storage content-type validation — only allow images; virus scanning via ClamAV or external API |

## 12. Performance Optimisations

| Area | Technique |
|---|---|
| Room availability queries | DB index on `(room_id, check_in_date, check_out_date)` in `booking_rooms` |
| Gallery images | Active Storage variants (thumbnail / medium / full) generated on upload via Solid Queue |
| Fragment caching | Room listings, facilities page — invalidated on admin update via `touch: true` |
| N+1 queries | `includes` / `eager_load` everywhere; Bullet gem in development |
| Image delivery | CDN (Cloudflare) in front of Active Storage S3/R2 bucket |
| Page load | Turbo Drive — SPA-like navigation without full page reloads |

```

   │

   │
   ▼
Kamal 2 (Docker deployment via SSH)
   │
```
