Mollika Inn - Booking System Flow

This document describes the actual booking architecture used in the current codebase.
It covers both:
1) the public guest booking flow
2) the admin manual booking flow

Important note:
- The public booking flow is handled by the main public controllers and routes.
- The admin booking flow is separate and is managed under the admin namespace.
- The route includes a POST /bookings/hold entry, but the current controller does not implement a matching action. The active public flow is check_availability -> new -> create -> show.

2. PUBLIC BOOKING ROUTES
------------------------------------------------------------

File: config/routes.rb

Public guest routes:
- GET /rooms
- GET /rooms/:slug
- GET /bookings/new
- POST /bookings
- GET /bookings/:id
- GET /bookings/check_availability
- POST /bookings/hold (declared in the route but not implemented in the current controller)

Actual public booking block:
resources :bookings, only: [ :new, :create, :show ] do
  collection do
    get  :check_availability
    post :hold
  end
end

This is the guest-facing flow that supports room search, booking form, and confirmation page.

------------------------------------------------------------
3. PUBLIC GUEST BOOKING PROCESS
------------------------------------------------------------

Step A: Guest sees room list
File: app/views/rooms/index.html.erb
- Lists room types
- Shows room prices and available room selection
- Generates links such as new_booking_path(...)

Example flow:
new_booking_path(room_type_slug: rt.slug, check_in: params[:check_in] || Date.today, check_out: params[:check_out] || Date.today + 1)

Step B: Guest checks availability
File: app/controllers/bookings_controller.rb
Action: check_availability
- Reads check_in and check_out from params
- Parses them into Date objects
- Finds room types with available rooms for that range
- Renders the availability partial:
  app/views/rooms/_availability_results.html.erb

Key logic:
- @check_in = Date.parse(params[:check_in])
- @check_out = Date.parse(params[:check_out])
- @room_types = RoomType.visible.ordered.select { |rt| rt.available_rooms_count(@check_in, @check_out) > 0 }

Step C: Guest opens booking form
File: app/controllers/bookings_controller.rb
Action: new
- Finds selected room type by slug
- Validates room_type_slug, check_in, and check_out values
- Rejects past dates and invalid ranges
- Calculates:
  - @nights
  - @price
  - @total
- Builds:
  - @booking = Booking.new
  - @guest = Guest.new

File: app/views/bookings/new.html.erb
- Displays booking summary
- Shows the room and date selection summary
- Displays guest detail form
- Displays stay details form
- Contains fields for:
  - first_name
  - last_name
  - email
  - phone
  - nationality
  - num_adults
  - num_children
  - special_requests
- Submits form to POST /bookings

Step D: Guest creates the booking
File: app/controllers/bookings_controller.rb
Action: create
- Re-validates room type and dates
- Builds a Guest object from nested params
- Checks if a guest already exists by email
- Validates guest data using Guest model validations
- Locates the first available room for the room type
- Creates a Booking record with values such as:
  - guest
  - check_in_date
  - check_out_date
  - num_adults
  - num_children
  - special_requests
  - status: "pending"
  - payment_status: "unpaid"
  - total_amount

Transaction flow:
- @guest.save! if the guest is new
- @booking.save!
- @booking.booking_rooms.create!(
    room: available_room,
    room_type: @room_type,
    rate_per_night: @price,
    total_amount: @price * @nights
  )

Finally:
- redirect_to booking_path(@booking)

Step E: Booking confirmation page
File: app/controllers/bookings_controller.rb
Action: show
- Loads the booking record by id

File: app/views/bookings/show.html.erb
- Shows the final booking confirmation page to the guest

4. PUBLIC BOOKING MODEL RELATIONSHIPS
------------------------------------------------------------

File: app/models/booking.rb
- belongs_to :guest
- has_many :booking_rooms, dependent: :destroy
- has_many :rooms, through: :booking_rooms
- has_many :room_types, through: :booking_rooms

Status values:
- pending
- confirmed
- checked_in
- checked_out
- cancelled

Payment status values:
- unpaid
- partial
- paid
- refunded

Core methods:
- confirm!
- check_in!
- check_out!
- cancel!
- nights
- balance_due
- display_guest_name

File: app/models/booking_room.rb
- Connects booking -> room -> room_type
- Stores rate_per_night and total_amount for the assigned room

File: app/models/room_type.rb
- Checks room availability with available_rooms_count
- Calculates the rate by date with price_for(check_in_date)
- Uses overlapping bookings to avoid double-booking

File: app/models/room.rb
- Holds room status like available, maintenance, or occupied
- has scope :available

File: app/models/guest.rb
- Validates first name, last name, email, phone, nationality
- Normalizes email formatting
- Prevents duplicate email addresses

6. ADMIN MANUAL BOOKING PROCESS
------------------------------------------------------------

Step A: Admin opens booking list
File: app/controllers/admin/bookings_controller.rb
Action: index
- Lists all bookings ordered by newest first
- Applies status filter if provided
- Applies payment status filter if provided
- Supports search by guest name, email, or booking id
- Applies date filters when params[:from] and params[:to] are present

File: app/views/admin/bookings/index.html.erb
- Displays the admin booking table
- Allows navigation to details and actions

Step B: Admin opens manual booking form
File: app/controllers/admin/bookings_controller.rb
Action: new
- Sets @booking = Booking.new
- Sets @guest = Guest.new
- Loads all room types from RoomType.includes(:rooms).ordered

File: app/views/admin/bookings/new.html.erb
- Contains fields for:
  - room type
  - payment status
  - check-in date
  - check-out date
  - num_adults
  - num_children
  - guest info
  - special requests
  - total amount

Step C: Admin submits a manual booking
File: app/controllers/admin/bookings_controller.rb
Action: create
- Parses dates and validates them
- Ensures check_out > check_in
- Requires a valid room type selection
- Builds a Guest object from guest params
- Checks for an existing guest by email
- Validates guest fields
- Finds the first available room in the selected room type
- Computes total using submitted_total or calculated value

Important logic:
- submitted_total = (booking_params[:total_amount].presence || 0).to_f
- computed_rate = @room_type.price_for(@check_in)
- nights = (@check_out - @check_in).to_i
- computed_total = (computed_rate * nights).to_f
- final_total = submitted_total > 0 ? submitted_total : computed_total

Then creates the Booking with:
- guest: @guest
- check_in_date
- check_out_date
- num_adults
- num_children
- special_requests
- status: "pending"
- payment_status: value or "unpaid"
- total_amount: final_total
- guest_name

And inside transaction:
- @guest.save! if new
- @booking.save!
- @booking.booking_rooms.create!(
    room: @room,
    room_type: @room_type,
    rate_per_night: @room_type.price_for(@check_in),
    total_amount: @booking.total_amount
  )

Success redirect:
- redirect_to admin_booking_path(@booking)

Step D: Admin booking detail view
File: app/controllers/admin/bookings_controller.rb
Action: show
- Finds the booking and loads it

File: app/views/admin/bookings/show.html.erb
- Displays booking details
- Contains actions for:
  - edit
  - confirm
  - check in
  - check out
  - cancel

Step E: Admin status actions
File: app/controllers/admin/bookings_controller.rb
Actions:
- confirm -> @booking.confirm!
- check_in -> @booking.check_in!
- check_out -> @booking.check_out!
- cancel -> @booking.cancel!(reason: params[:reason])

These methods are defined in app/models/booking.rb.

7. GUEST PORTAL BOOKING (OPTIONAL)
------------------------------------------------------------

The app also includes a guest portal namespace:
namespace :guests do
  resource :session
  resource :profile
  resources :bookings, only: [ :index, :show ] do
    member { patch :cancel }
  end
end

Files involved:
- app/controllers/guests/bookings_controller.rb
- app/views/guests/bookings/index.html.erb
- app/views/guests/bookings/show.html.erb

This is a separate guest experience from the public booking form and is not the main public booking workflow.
